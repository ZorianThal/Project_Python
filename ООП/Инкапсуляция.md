## 1. Идея

> [!note] Определение
> **Инкапсуляция** состоит из двух связанных идей:
> 1. **Объединение** данных и методов, которые с ними работают, в одном объекте.
> 2. **Ограничение прямого доступа** к внутреннему состоянию: менять его можно только через контролируемый интерфейс.

> [!tip] Аналогия
> Автомобиль. Вы пользуетесь рулём и педалями (интерфейс). Вы не лезете руками в топливную систему. Производитель может заменить двигатель, а вы продолжите ездить так же.

## 2. Зачем это нужно

| Проблема без инкапсуляции | Что даёт инкапсуляция |
|---|---|
| Любой код может записать в объект мусор (`age = -5`) | Проверка значений в одном месте |
| Нарушаются связи между полями | Объект всегда в согласованном состоянии (**инвариант**) |
| Изменение внутренней структуры ломает весь код, который её использует | Внутреннее устройство можно менять, интерфейс остаётся |
| Сложно найти, кто испортил данные | Все изменения идут через несколько методов |

> [!important] Инвариант
> **Инвариант** это условие, которое должно быть истинным для объекта всегда. Например: «баланс счёта не отрицателен», «ширина прямоугольника положительна». Задача инкапсуляции: не дать инвариант нарушить.

### Пример проблемы

```python
class Account:
    def __init__(self, balance):
        self.balance = balance

acc = Account(100)
acc.balance = -99999        # никто не помешал
```

## 3. Уровни доступа в Python

В Python **нет** ключевых слов `private` и `protected`. Работают соглашения.

| Запись | Название | Что значит |
|---|---|---|
| `name` | публичный | Часть интерфейса, можно использовать снаружи |
| `_name` | «защищённый» | Договорённость: внутреннее, снаружи не трогать (но технически доступно) |
| `__name` | «приватный» | Python переименовывает атрибут (name mangling) |
| `__name__` | магический | Зарезервирован за Python, свои так не называть |

> [!quote] Философия Python
> «Мы все здесь взрослые люди» (*we are all consenting adults*). Язык не запрещает, а предупреждает: подчёркивание означает «если полезешь, отвечаешь сам».

### 3.1 Одинарное подчёркивание `_name`

```python
class User:
    def __init__(self, name):
        self._name = name       # внутренний атрибут

u = User("Анна")
print(u._name)                  # работает, но это нарушение соглашения
```

Дополнительно: `from module import *` не импортирует имена с `_` в начале.

### 3.2 Двойное подчёркивание `__name` (name mangling)

```python
class Secret:
    def __init__(self):
        self.__code = 1234

s = Secret()
# print(s.__code)              # AttributeError
print(s._Secret__code)         # 1234: переименовано в _КлассИмя__атрибут
print(s.__dict__)              # {'_Secret__code': 1234}
```

> [!warning] Это не настоящая защита
> Name mangling нужен **не для безопасности**, а чтобы атрибуты родителя и потомка с одинаковыми именами не конфликтовали.

```python
class Parent:
    def __init__(self):
        self.__x = "родитель"
    def get_parent_x(self):
        return self.__x          # на самом деле _Parent__x

class Child(Parent):
    def __init__(self):
        super().__init__()
        self.__x = "потомок"     # на самом деле _Child__x, не затирает родительский

c = Child()
print(c.get_parent_x())          # родитель
```

> [!tip] Что выбирать на практике
> Почти всегда достаточно `_name`. Двойное подчёркивание применяют редко: в библиотечных базовых классах, когда нужно защититься от случайного перекрытия имени в наследниках.

### 3.3 Приватные методы

То же самое работает для методов:

```python
class Report:
    def build(self):
        data = self._collect()
        return self._format(data)

    def _collect(self):          # внутренняя кухня
        return [1, 2, 3]

    def _format(self, data):
        return ", ".join(map(str, data))
```

## 4. Геттеры и сеттеры: путь Java и путь Python

### 4.1 Как делают в Java (в Python так не пишут)

```python
class Person:
    def __init__(self, age):
        self._age = age
    def get_age(self):
        return self._age
    def set_age(self, value):
        if value < 0:
            raise ValueError("Возраст не может быть отрицательным")
        self._age = value

p = Person(20)
p.set_age(21)        # громоздко
```

### 4.2 Путь Python: `@property`

> [!note] Идея
> Начинаем с **обычного публичного атрибута**. Если позже понадобится проверка, превращаем его в `property`, и **внешний код не меняется**: по-прежнему `p.age`, а не `p.get_age()`.

```python
class Person:
    def __init__(self, age):
        self.age = age                   # важно: идёт через сеттер!

    @property
    def age(self):                       # геттер
        return self._age

    @age.setter
    def age(self, value):                # сеттер
        if not isinstance(value, int):
            raise TypeError("Возраст должен быть целым числом")
        if value < 0:
            raise ValueError("Возраст не может быть отрицательным")
        self._age = value

    @age.deleter
    def age(self):                       # удаление (используется редко)
        print("Удаляем возраст")
        del self._age


p = Person(20)
p.age = 21               # вызывается сеттер
print(p.age)             # вызывается геттер
# p.age = -5             # ValueError
```

> [!warning] Важная деталь
> В `__init__` пишем `self.age = age`, а **не** `self._age = age`. Тогда проверка срабатывает и при создании объекта. Иначе можно создать `Person(-5)` в обход валидации.

### 4.3 Свойство только для чтения

Не определяем сеттер:

```python
class Circle:
    def __init__(self, r):
        self.r = r

    @property
    def area(self):
        return 3.14159 * self.r ** 2

c = Circle(2)
print(c.area)        # 12.56636
# c.area = 100       # AttributeError: can't set attribute
```

### 4.4 Вычисляемые свойства

Значение не хранится, а считается по требованию. Это исключает рассинхронизацию данных.

```python
class Rectangle:
    def __init__(self, w, h):
        self.w = w
        self.h = h

    @property
    def area(self):
        return self.w * self.h

    @property
    def is_square(self):
        return self.w == self.h

r = Rectangle(3, 3)
r.w = 5
print(r.area)        # 15: всегда актуально
```

> [!tip] Если бы `area` хранили как обычный атрибут
> После `r.w = 5` площадь осталась бы старой. Вычисляемое свойство решает проблему.

### 4.5 Кэширование: `functools.cached_property`

```python
from functools import cached_property

class Dataset:
    def __init__(self, values):
        self.values = values

    @cached_property
    def mean(self):                 # посчитается один раз
        print("Считаем...")
        return sum(self.values) / len(self.values)

d = Dataset([1, 2, 3])
print(d.mean)    # Считаем... 2.0
print(d.mean)    # 2.0 (из кэша)
```

## 5. Защита инвариантов через методы

Часто правильное решение это **не сеттер, а метод с осмысленным именем**.

```python
class BankAccount:
    def __init__(self, balance=0):
        if balance < 0:
            raise ValueError("Начальный баланс не может быть отрицательным")
        self._balance = balance
        self._history = []

    @property
    def balance(self):               # только чтение
        return self._balance

    def deposit(self, amount):
        if amount <= 0:
            raise ValueError("Сумма должна быть положительной")
        self._balance += amount
        self._history.append(("deposit", amount))

    def withdraw(self, amount):
        if amount <= 0:
            raise ValueError("Сумма должна быть положительной")
        if amount > self._balance:
            raise ValueError("Недостаточно средств")
        self._balance -= amount
        self._history.append(("withdraw", amount))
```

> [!important] Почему нет сеттера для `balance`
> `account.balance = 500` не говорит, *почему* баланс изменился, и не записывается в историю. Методы `deposit` и `withdraw` выражают **бизнес-операции** и защищают инвариант. Хороший интерфейс описывает, что можно **делать** с объектом, а не какие поля можно **перезаписать**.

## 6. Утечка внутреннего состояния

> [!warning] Частая ошибка
> Если геттер возвращает ссылку на изменяемый внутренний объект, снаружи его можно изменить, **обойдя всю защиту**.

```python
class Team:
    def __init__(self):
        self._members = ["Анна", "Иван"]

    @property
    def members(self):
        return self._members          # УТЕЧКА: отдали сам список

t = Team()
t.members.append("Хакер")             # защита обойдена
print(t.members)                      # ['Анна', 'Иван', 'Хакер']
```

**Решения:**

```python
@property
def members(self):
    return list(self._members)        # копия

@property
def members(self):
    return tuple(self._members)       # неизменяемый вид
```

```python
def add_member(self, name):           # изменение только через метод
    if not name:
        raise ValueError("Имя не может быть пустым")
    self._members.append(name)
```

## 7. Сводка: что чем защищать

| Задача | Инструмент |
|---|---|
| Пометить атрибут как внутренний | `_name` |
| Избежать конфликта имён в наследовании | `__name` |
| Проверить значение при записи | `@property` + `setter` |
| Запретить запись | `@property` без сеттера |
| Хранить производное значение без рассинхронизации | вычисляемый `@property` |
| Защитить внутренний изменяемый объект | возвращать копию или `tuple` |
| Выразить бизнес-операцию | метод с понятным именем |

## 8. Типичные ошибки

> [!warning] Проверьте свой код
> 1. В `__init__` пишут `self._x = x` вместо `self.x = x` и теряют валидацию при создании.
> 2. Внутри геттера обращаются к `self.x` вместо `self._x`: бесконечная рекурсия.
> 3. Делают сеттер для каждого поля «на всякий случай». Лишние сеттеры разрушают инкапсуляцию.
> 4. Возвращают из геттера изменяемую внутреннюю коллекцию.
> 5. Принимают изменяемый аргумент в `__init__` и сохраняют без копии: внешний код продолжает им владеть.
> 6. Считают `__name` настоящей защитой.

```python
# Ошибка №2: рекурсия
@property
def age(self):
    return self.age        # RecursionError: геттер вызывает сам себя

# Ошибка №5: утечка через аргумент
class Team:
    def __init__(self, members):
        self._members = members          # лучше list(members)

lst = ["Анна"]
t = Team(lst)
lst.append("Кто-то")                     # изменил состояние объекта снаружи
```

## 📌 Решения

### Задание 1

```python
class Temperature:
    def __init__(self, celsius):
        self.celsius = celsius                 # через сеттер

    @property
    def celsius(self):
        return self._celsius

    @celsius.setter
    def celsius(self, value):
        if value < -273.15:
            raise ValueError("Ниже абсолютного нуля")
        self._celsius = value

    @property
    def fahrenheit(self):
        return self._celsius * 9 / 5 + 32

    @fahrenheit.setter
    def fahrenheit(self, value):
        self.celsius = (value - 32) * 5 / 9    # снова через сеттер celsius

t = Temperature(100)
print(t.fahrenheit)     # 212.0
t.fahrenheit = 32
print(t.celsius)        # 0.0
```

### Задание 2

```python
class User:
    def __init__(self, username, password):
        if not isinstance(username, str) or not username.strip():
            raise ValueError("Имя пользователя не может быть пустым")
        self._username = username
        self.password = password                # через сеттер

    @property
    def username(self):
        return self._username

    @property
    def password(self):
        raise AttributeError("Пароль нельзя прочитать")

    @password.setter
    def password(self, value):
        if len(value) < 6:
            raise ValueError("Минимум 6 символов")
        self._password = value

    def check_password(self, pwd):
        return pwd == self._password

u = User("anna", "secret123")
print(u.check_password("secret123"))   # True
# print(u.password)                    # AttributeError
# u.username = "x"                     # AttributeError
```

> [!tip] Замечание
> В реальных системах пароль хранят в виде хеша (`hashlib`, `bcrypt`), а не открытым текстом. Здесь упрощено ради темы.

### Задание 3

```python
class Cart:
    def __init__(self):
        self._items = {}                       # {name: (price, qty)}

    def add(self, name, price, qty=1):
        if price < 0 or qty <= 0:
            raise ValueError("Некорректные цена или количество")
        if name in self._items:
            old_price, old_qty = self._items[name]
            self._items[name] = (price, old_qty + qty)
        else:
            self._items[name] = (price, qty)

    def remove(self, name):
        self._items.pop(name, None)

    @property
    def items(self):
        return dict(self._items)               # копия

    @property
    def total(self):
        return sum(price * qty for price, qty in self._items.values())

c = Cart()
c.add("Хлеб", 50, 2)
c.add("Молоко", 80)
print(c.total)                 # 180
c.items["Хакер"] = (0, 1)      # меняем копию
print(c.total)                 # 180: корзина не пострадала
```

### Задание 6

```python
class TrafficLight:
    _ORDER = ("red", "green", "yellow")

    def __init__(self):
        self._index = 0

    @property
    def state(self):
        return self._ORDER[self._index]

    def next(self):
        self._index = (self._index + 1) % len(self._ORDER)
        return self.state

tl = TrafficLight()
print(tl.state)     # red
print(tl.next())    # green
print(tl.next())    # yellow
print(tl.next())    # red
```
